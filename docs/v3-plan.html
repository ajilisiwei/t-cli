    4. 数据模型

    一张新表、materials 两处改动、七个新设置。迁移 0003 只加不删，旧客户端不受影响。

    改动内容
    lookup_events（新表）列：user_id、id（ULID）、lemma_key（与 lexicon.lemma 同一规则）、explain_lang、created_at。主键 (user_id, id)，索引 (user_id, created_at)。不存句子，不存 entryId。同一账号同一个词 10 分钟内只记一次。180 天前的事件由夜间任务删除
    materials.kind增加 digest（每周模式的 7 天合集）和 extend（拓展资料）。date 的含义：daily 是内容所属的那天；digest 是覆盖区间的最后一天；extend 是生成那天；weekly 不变
    materials.read_at（新列）timestamptz，可空。「学完了」写入，撤销清空
    items不加列。点词转来的单元和加入复习的拓展条目都用现有的 lookupCount、stars、status

    新设置（POST /v1/me/settings，先存本地再同步）

    键取值默认
    materialFrequencydaily / weekly / offdaily
    materialWeekday0–6，0 是周日1（周一）
    materialPartswords、phrases、grammar、story、exercises 的子集，至少 1 项全部
    extendEnabledtrue / falsetrue
    extendTopicswork、travel、exam、daily、tech、culture、finance、health 的子集；空表示只用自动识别[]
    extendMuted[{topic, until: "YYYY-MM-DD"}]，最多 8 条[]
    studyLevelauto / A2 / B1 / B2 / C1auto
    资料内容的结构
    • daily：沿用 DailyMaterial，不变。
    • digest：DailyMaterial 的字段，加上 range: {start, end}；上限放宽到单词 20、词组 10、语法 6、易错 8；另加 review（最多 12 个本周复习时忘过的单元），一周没有新内容时它就是主体。
    • extend：{focus, topic, title, level, reasons[], evidence[], items[6–10]{text, kind, gloss, example{en, zh}}, passage | null, grammar | null}。focus 是 topic / family / grammar / reading 之一。
    • 练习不存库：选词填空从单词和词组的例句里挖空，中译英用例句的中英对照，改错沿用语法点自带的练习。一个纯函数 exercisesFor(material) 同时供接口和 PDF 使用，不调用模型。

    5. 接口

    四个新接口，五个改动接口；契约写进 docs/api-v1.md 的新章节「v3 (M12–M17)」。

    接口做什么要点
    POST /v1/lookup响应不变；成功后写一条查词事件写失败只记日志，不影响响应；不增加查词耗时
    GET /v1/learn/summary（新）学习首页一次取齐dueByScope {all, notes, stars3}、doneToday、streakDays、估计分钟数、最近 3 份资料、计划摘要、level {setting, effective, retention30}
    GET /v1/review/queue?scope=按范围取复习队列all（默认）/ notes（星级 ≥ 1）/ stars3（星级 ≥ 3）
    GET /v1/materials?kind=资料列表kind = all / daily / digest / extend / weekly；按 date 倒序翻页；每项带 title、counts、readAt、估计页数
    GET /v1/materials/:kind?date=资料内容新增 digest、extend；带推导出的 exercises；extend 的每一条带 known（已在复习）
    POST /v1/materials/:kind/:date/read（新）学完了 / 撤销body {read: boolean}
    POST /v1/materials/extend/:date/adopt（新）把勾选的条目加入复习body {indexes: number[]} → {added, known}；可重复调用。词库里有这个词的当场出卡片，其余次日夜间出
    POST /v1/materials/extend/:date/dismiss不感兴趣 / 撤销把这份资料的 topic 写进 extendMuted，30 天后自动失效
    POST /v1/exports/pdf（新）生成 PDF见第 8 节。返回 application/pdf；每账号每小时 10 次；最多 40 页
    POST /v1/me/settings接受第 4 节的新键旧客户端不发这些键，行为不变

    6. 关键链路：夜间任务

    每个账号多两步：第 0 步把点词转成学习单元，第 5 步出拓展资料；第 3 步按频率决定今天出什么。30 天没有活动的账号跳过第 3 步和第 5 步。

    • 第 0 步：上次运行以来的查词事件按 lemma_key 合并。已有单元的 lookupCount 加上次数，并更新 lastSeenAt；没有的新建 word 单元。词库里有这个词时，单元直接是 ready 并出卡片；没有时是 pending，交给第 2 步。
    • 活动：记录、查词事件、笔记、复习，任意一种都算。每日资料原来只看记录，现在四种都算。
    • 每周合集：在选定星期的早上出，覆盖前 7 天。这一周没有新内容时，主体是「本周复习时忘过的」。
    • 难度（auto）：默认 B1。最近 30 天记住率 ≥ 88% 且复习 ≥ 150 次 → B2；≥ 93% 且 ≥ 300 次 → C1；低于 70% → A2；复习少于 50 次保持 B1。
    • materialParts：关掉「情景短文」就不调用模型写短文，省下这次调用。

    7. 关键链路：拓展资料

    模型只挑方向和内容；推荐理由由服务端用统计数字拼出来，所以理由不会编造。

    Mermaid 源码 
    sequenceDiagram
  participant N as 夜间任务
  participant DB as 数据库
  participant AI as DeepSeek
  participant A as 小程序
  N->>DB: 读信号（只取词、语法点标题和次数）
  N->>AI: 一次 JSON 调用
  AI-->>N: focus、topic、evidence、条目
  N->>N: 校验；evidence 不在给出的词里就删掉
  N->>N: 用 evidence 和统计数字拼推荐理由
  N->>DB: 存 materials(extend)
  A->>DB: 读拓展资料（每条标 known）
  A->>DB: adopt 勾选的条目
  Note over DB: 次日夜间生成内容和卡片
    • 信号：14 天内查过和记录里出现的词（最多 60 个）、纠错里的语法点和次数、复习时忘过的单元（最多 10 个）、3 星以上的单元、难度、方向、被静音的主题。不发任何用户句子。
    • 校验：zod 校验结构；evidence 至少要有 2 个来自给出的词，否则重试一次，还不行就这周不出。
    • 理由模板：「最近 7 天你查了 X、Y 等 N 个职场用词」「X 在复习时忘了 2 次」「纠错里『冠词』出现了 4 次」「按你最近 82% 的记住率，难度定在 B1–B2」。
    • 成本：每账号每周一次调用，约 3 千 token，在每次 20 万 token 的预算里。

    8. PDF 导出

    服务端用 Typst 排版，数据只通过 JSON 文件进入模板；小程序拿到字节后写成本地文件，再预览或转发。

    Mermaid 源码 
    sequenceDiagram
  participant A as 小程序
  participant S as API
  participant T as Typst
  A->>S: POST /v1/exports/pdf（范围、版式、选项）
  S->>S: 读资料，推导练习，组装 data.json
  S->>T: 临时目录里编译固定模板
  T-->>S: PDF 字节（stdout）
  S-->>A: application/pdf
  A->>A: 写到 USER_DATA_PATH/exports
  A->>A: 预览 openDocument 或 发送 shareFileMessage
    方面做法
    渲染器Typst 0.13.1 静态二进制（musl，x86_64），版本和 sha256 固定在 Dockerfile 里
    字体思源宋体 SC（Noto Serif SC）常规和粗体，Source Serif 4 常规、斜体、半粗、粗体；都用静态字重文件（Typst 0.13 只认可变字体的默认字重）；OFL 许可文件一起放；镜像约增大 60 MB
    安全模板是仓库里的固定文件；用户数据只写进 data.json，模板用 json() 读入，按纯文本排版，排版指令不会被执行（已实测）。每次请求一个临时目录，--root 指向它，--ignore-system-fonts；15 秒超时就结束进程；同时最多 2 个渲染；PDF 不在服务端保存
    实测本机 0.13.1：4 页带中文和音标，约 0.1 秒，峰值约 50 MB，PDF 37–60 KB（字体只嵌入用到的字）
    版式A4，页边 19 mm；页眉资料名和日期，页脚页码；正文 11.5 pt。练习版的答案在最后一节，前面有一条剪切线。单词卡每页 6 张，实线剪开、竖线对折（左右翻面时背面是正的）。自测清单沿中间虚线对折。只有标题编号用靛青，黑白打印也清楚
    小程序wx.request（arraybuffer）→ 写到 USER_DATA_PATH/exports/ → wx.openDocument({showMenu: true}) 预览。「发给微信好友」在点击回调里直接调 wx.shareFileMessage。导出记录存在本地，7 天后删除文件
    错误超过频率限制返回 429；超过 40 页返回 422 TOO_MANY_PAGES；渲染失败或超时返回 502 EXPORT_FAILED。日志只记页数、耗时和结果，不记内容

    11. 风险与应对

    风险应对
    渲染占内存，256 MB 的容器被 OOM 杀掉同时最多 2 个渲染；M15 在镜像里按 256 MB 实测。不够时把上限调到 384 MB，这要你确认（主机约有 890 MB 空闲）
    镜像增大约 60 MB只放两个中文字重；Typst 用静态二进制；字体单独一层，构建时走缓存
    AI 成本增加拓展资料每周一份；30 天没有活动的账号不生成；合集只多一次短文调用；都在每个账号每次 20 万 token 的预算里
    推荐理由编造理由由服务端用统计数字拼出；模型只能从给出的词里选依据，不在列表里的会被删掉
    查词事件太多同一个词 10 分钟内只记一次；只存 lemma key 和时间；180 天后删除
    隐私事件不存句子；PDF 不在服务端保存；日志不记内容

    13. 术语表

    术语含义
    周期资料按你设的频率出的资料。每天模式是每日资料（daily），每周模式是 7 天合集（digest）
    拓展资料AI 推荐的、你还没接触到的相关内容（extend），每周一份
    查词事件点词查词成功后记下的一条记录：什么时候查了哪个词
    学习单元一个词、词组、语法点或句子（item）；复习卡片从它生成
    复习范围全部到期、只复习笔记本、3 星以上
    阅读版 / 练习版PDF 的两种版式。阅读版直接给出释义和答案；练习版把答案放在最后一节
    单词卡可以剪开、对折的卡片，正面单词，背面释义
    自测清单左栏单词、右栏释义，对折遮住右栏自测
    Typst服务端用来把数据排成 PDF 的排版程序
