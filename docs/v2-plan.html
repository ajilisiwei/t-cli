随手译记 v2 实现计划

    技术方案 · 2026-11-24 · 来源：v2 原型（claude.ai/artifact/2pbXQ1go8hwtCU5HaMUtyg）、代码库 main 分支
    v2 把翻译和纠错合到一页，新增点词查词、带星级的笔记本和按天分组的记录页。 服务端先改数据和接口（M6、M7），再改小程序和 CLI（M8–M10），最后发布（M11）。 多语种这一版只做数据层的地基，设置里先不开放「母语 / 学习语言」，原因见第 12 节。

    1. 范围与已定设计

    v2 包含 8 项改动，设计已在原型里定稿；下表是每项的最终设计。

    改动定下的设计原型画板
    翻译页合一「纠错」「翻译」两个按钮并排；方向自动识别；方向按钮默认隐藏，设置里可打开；输入框空着时提示「输入或〔粘贴〕要翻译或纠错的文字」，点「粘贴」读剪贴板；输入中文时「纠错」置灰翻译 · 空态、单词结果、句子结果、纠错结果
    点词查词句子结果里英文一侧的每个词都能点；底部面板显示「在本句中」、释义和所在词组；按原形查（decisions → decision）句子结果、长段落点词
    笔记本与星级笔记本替换「纠错」tab；单词、词组、句子都能收藏；点书签收藏，默认 1 星；宽操作栏的星星长在书签右边，窄行的星星在文字下方另起一行（方案 B）笔记本、收藏星级三种放法
    单词详情美式和英式音标、在本句中、释义、词形、搭配、例句、近义辨析、记忆、我的记录；不显示考试标签和常用度单词详情模板
    记录页按天分组；日期条按天筛选并显示条数；日历按钮跳到任意一天；按来源（手机 / CLI）筛选；搜索查询记录
    设置与外观主题色 5 种；深浅模式（跟随系统 / 跟随时间 / 固定）；阅读模式；按星级安排复习；所有设置先存本地再同步到账号；纸张第一期只有宣纸设置、外观
    长文本输入框提交后折叠；结果超过一屏时操作栏吸底；原文超过 6 行折叠；纠错解释先显示 3 条；列表截断；超过 1000 字分段朗读长文本与边缘情况一排
    通用朗读、复制、收藏只用图标；翻译只复制译文（单词只复制释义那一行）；纠错只复制修改后的句子；tab 栏带图标全部
    不在 v2 里：宣纸以外的纸张和纸纹、多语种界面、H5 端。长按拖选词组也不做，先用「再点相邻的词扩展选择」。

    表 / 列变化说明
    notes新增一条笔记 = 用户收藏的一个单词、词组或句子。主键 (user_id, id)。id 由客户端生成 ULID，重复提交不产生重复行。
    kind：word / phrase / sentence
    text、translation：笔记的原文和译文
    lang：BCP 47 代码，如 en
    stars：1–4
    entry_id：来源记录，可空
    item_id：对应的学习单元
    seq：同步序号
    deleted_at：软删除标记，供同步
    lexicon新增词条缓存：单词详情的 JSON。主键 (lang, explain_lang, lemma, version)。不存用户 id，也不存原句
    items.stars新增列smallint，默认 0（未收藏）。值 = 指向它的有效笔记里的最高星级，在写笔记的同一个事务里更新
    items.type加 sentence句子笔记对应的学习单元。content = {text, translation}，不调用 AI
    cards.card_type加 recall句子卡片：正面译文，背面原句（看译文说原句）
    entries加索引input 列加 pg_trgm GIN 索引，供记录页搜索
    users.settings加键showDirection、accent、themeMode、themeFixed、readingMode、readingFontStep、importanceReview（见第 5 节）
    词条 JSON 的字段（lexicon.content）

    字段名不带语言（用 gloss，不用 zh），为多语种留余地：

    { lemma, ipa: {us, uk}, senses: [{pos, gloss, def}], forms: [{label, form}], collocations: [{text, gloss}], examples: [{text, gloss}], contrasts: [{word, note}], memory }

    收藏单词时，服务端用词条直接生成学习单元的 content。content 沿用已有的 word 结构：headword、ipa、meanings、examples、collocations、synonyms、family。卡片当场生成，不用等夜间流水线。

    5. 接口

    新增 6 个接口，改 3 个；全部写进 docs/api-v1.md，旧接口行为不变。

    接口变化说明
    POST /v1/lookup新增body {word, sentence?, entryId?} → {lemma, entry, context, phrase?}。entry 来自词条缓存；context 是「在本句中」，phrase 是这个词所在的词组。计入 AI 请求配额
    PUT /v1/notes/:id新增新建或更新一条笔记（含星级）。同一事务里建立或关联学习单元，生成卡片，更新 items.stars
    DELETE /v1/notes/:id新增取消收藏：软删除，重算 items.stars
    GET /v1/notes新增笔记本列表：按 kind、stars 筛选，按加入时间倒序翻页
    GET /v1/notes/changes?after=<seq>新增增量同步，带删除标记；小程序和 CLI 共用
    GET /v1/entries/days新增参数 from、to、utcOffsetMinutes、source；返回每个本地日期的条数，供日期条使用
    GET /v1/entries/history改加参数 date、source、q（搜索 input）
    POST /v1/tts改加参数 part；服务端按句子切成每段最多 1000 字，响应头 X-Speech-Parts 返回总段数
    POST /v1/me/settings改接受 7 个新设置键：
    showDirection：布尔，默认 false
    accent：indigo / pine / plum / ochre / ink
    themeMode：system / time / fixed
    themeFixed：light / dark
    readingMode：布尔
    readingFontStep：0–3
    importanceReview：布尔，默认 true

    设置改为「先存本地，再同步账号」，流程如下：

    6. 关键链路：点词查词与收藏

    点词时服务端先查词条缓存，没命中才调 AI；收藏时当场生成学习单元和卡片。

    Mermaid 源码 
    sequenceDiagram
    participant M as 小程序
    participant S as 服务端
    participant L as 词条缓存
    participant D as DeepSeek
    M->>S: POST /v1/lookup（词 + 句子）
    S->>L: 按语言 + 原形查
    L-->>S: 命中或未命中
    S->>D: 未命中时生成词条
    S->>L: 写入新词条
    S->>D: 生成「在本句中」
    D-->>S: 句中释义 + 词组
    S-->>M: 原形、词条、句中释义
    M->>S: PUT /v1/notes/:id（1 星）
    S->>S: 写笔记、建学习单元和卡片
    S-->>M: 笔记（含星级）

    句子笔记不走查词：学习单元直接用记录的原文和译文，不调用 AI。

    1. 小程序把英文一侧切成词（新模块 lib/tokens.ts：字母、撇号、连字符算一个词）。
    2. 点一个词，发 POST /v1/lookup；面板先显示骨架，返回后填入。
    3. 如果面板挡住选中的词，页面自动上滚。
    4. 点相邻的词把选择扩展成词组，再查一次。
    5. 点书签发 PUT /v1/notes/:id；离线时写入本地待发队列（照搬复习评分的待发队列）。

    7. 复习：星级怎么影响排期

    星级决定两件事：每张卡片的目标记住率，以及新卡出现的先后。目标记住率越高，间隔越短，复习越勤。

    星级目标记住率新卡顺序每日材料
    未收藏（夜间自动提取）0.85（现在是 0.90）最后照常
    1 星（收藏默认）0.90先于未收藏照常
    2 星0.92↑照常
    3 星0.94↑优先选入
    4 星0.95（上限）最先优先进单词和情景短文
    注意：收藏默认是 1 星，所以 1 星的记住率不能低于未收藏的词，否则收藏反而复习得更少。原型便签里写的「1 星 = 80%」要按上表改。记住率超过 0.95 后复习量增长很快，所以封顶 0.95。
    1. fsrs.ts 的全局常量改成 schedulerFor(retention)，按记住率缓存 5 个调度器实例。
    2. 卡片的记住率 = 映射(items.stars)；设置里关掉「按重要程度安排复习」时，全部用 0.90。
    3. 卡片状态本来就是从评分日志重放出来的（review/cards.ts:66-85）。改星级后，下次重放就按新的记住率算间隔，不重置进度。
    4. 队列排序（review/queue.ts:154-196）：新卡先按 stars 降序，再按现有的分数排。
    5. 每日材料选词（pipeline/materials.ts）优先选 3 星和 4 星的学习单元。

    未收藏的词从 0.90 降到 0.85，现有用户的复习量会减少。这一映射已确认（2026-11-24）。

    9. CLI 改动

    CLI 只加笔记本的两条命令；复习排期在服务端完成，CLI 不用改。

    • /note [1-4]：收藏上一条结果，默认 1 星。单词记成单词笔记，句子和纠错记成句子笔记。
    • /notebook [word|phrase|sentence]：列出笔记本，带星级。
    • 设置同步：CLI 只读写释义语言，新增的键原样保留，不受影响。
    • CLI 默认释义语言是 en（apps/cli/src/config.js:17），小程序和服务端默认是 zh。这一版改成 zh。

    11. 风险与应对

    最大的风险是查词的成本和速度；其次是两个一定会遇到的小程序限制（tab 栏颜色、剪贴板声明）。

    风险可能性影响应对
    每次点词都调 AI，费用高、等待长高中词条全站缓存；「在本句中」用短提示词；面板先显示骨架；计入配额
    AI 释义有错中中页面标注「AI 生成」；「报错」后重新生成并清除该条缓存
    强制深色时原生 tab 栏仍是浅色必然低切换主题时调 wx.setTabBarStyle
    tab 栏图标只能用 PNG，主题色要多套图必然低脚本生成：未选中 4 × 2 套，选中 4 × 2 × 5 套，共 48 张
    未声明剪贴板，读取失败必然中先在后台声明；失败时提示长按输入框粘贴
    长按拖选词组在 Skyline 难做中低v2 改为「再点相邻的词扩展选择」
    翻译和纠错合页后状态变复杂中中状态机放 lib，补单元测试

    12. 多语种：母语与学习语言

    加「母语 + 学习语言」是对的方向，但它不是一个开关：代码里 40 多处写死了「中文母语学英文」。建议 v2 只做数据层的地基，设置里先不开放。

    先定义 3 个概念，全文只用这 3 个名字：

    • 母语：界面文字和默认释义用的语言。

    • 释义语言：保留现在的 explanationLang，改成二选一：用母语，或用学习语言（沉浸）。

    建议的阶段

    阶段内容
    P0（放在 v2 里）新表带 BCP 47 语言代码（notes.lang；lexicon 的键含学习语言和释义语言）；新 JSON 字段用 gloss，不用 zh；新代码从一个「语言对」取值，不再新写 zh / en 常量；设置里不开放
    P1 英文母语学中文界面 i18n（先中、英两套）；中文分词和拼音；中文纠错提示词；卡片文案按语言对生成
    P2 西、法、德语语言识别；各语言的词条模板；IPA 读音
    P3 日、韩语分词；假名或罗马字；敬语等语法分类
    不做阿拉伯语、希伯来语等从右到左书写的语言
    为什么 P1 选「英文母语学中文」：它只用到现有的两种语言，不需要新的识别模型；但它会逼出最难的两件事：界面 i18n 和中文分词。这两件做通了，后面加语言主要是加模板和提示词。

    开放设置后的规则：母语和学习语言各选一个；换学习语言时，笔记本、复习、统计按语言分开显示，旧数据保留，不删除。 推断

    14. 术语表

    术语含义
    笔记用户收藏的一个单词、词组或句子；notes 表的一行
